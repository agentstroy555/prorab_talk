# Прораб Talk + Parabtalk — v0.3.3 (build 11)

Мобильный voice-first прототип Agent Stroy для создания заявки на стройматериалы.

## Что проверяем в v0.2

Рекомендуемый формат диктовки: **товар → вариант SKU → количество**.

Пример: `Rotband → 25 кг → 30 мешков`.

Каталог теперь имеет дополнительное иерархическое JSON-представление в `data/catalog-structured.json`: семейство товара содержит типовую единицу заказа и массив конкретных SKU-вариантов. На этой итерации вариант остаётся одной строкой, поэтому, например, размер самореза `4,8×60 мм` хранится единым сегментом.

Интерфейс ориентирован прежде всего на телефон в портретной ориентации:
- fixed floating voice pill;
- Play/Pause/Stop;
- «Далее» с индикатором тишины;
- живой индикатор уровня микрофона;
- новые позиции сверху;
- отдельно исправляемые сегменты товара и варианта;
- количество + единица;
- «Уточнить» переразбирает всю строку и после Stop не возобновляет основной сеанс автоматически;
- склейка соседних строк через +.

## Локальный запуск

Node.js 24.x и PostgreSQL.

```bash
cp .env.example .env
npm install
npm test
npm run dev
```

Заполните `DATABASE_URL` и `GROQ_API_KEY` в `.env`.

## Render

Для существующего Render service: [инструкция web + Telegram](docs/RENDER.md). По умолчанию TELEGRAM_ENABLED=false сохраняет web-only запуск.

`render.yaml` описывает прежний free web baseline и PostgreSQL, без включённого бота. `DATABASE_URL` связывается с Blueprint-базой автоматически, `GROQ_API_KEY` вводится как secret environment variable.

## Telegram в том же сервисе

`npm start` запускает один сервер для сайта и опционального бота. Каталог и parser общие; web-заявки остаются в PostgreSQL, Telegram-данные — SQLite на постоянном диске. Сметы между каналами автоматически не синхронизируются. Новых web UX функций этот релиз не добавляет.

Проверки из корня: `npm run check`, `npm test`, `npm run demo:telegram`. Подробности бота: [telegram/README.md](telegram/README.md). Токен задаётся в Render Environment; в публичных исходниках секрета нет.
