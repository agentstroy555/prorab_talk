# Проверки v0.3.4 (build 12)

Дата: 2026-10-25. Окружение: Linux, Node.js 24.22.1. Локальные автоматические проверки, **не live Telegram/Groq acceptance**.

## Выполнено

- `npm run check` — синтаксис исходников, scripts и tests.
- `npm test` из telegram/ — 72 теста, реальные in-memory/file-backed SQLite и локальный HTTP server; внешние Telegram/Groq заменены адаптерами.
- `npm run demo` — полный разговор: новая смета → голос → коррекция количества → завершение → CSV/JSON, без сети.
- Build 12: из корня 29 web/integration + 72 Telegram тестов. Реальные HTTP listener и SQLite, fake PostgreSQL/Telegram/Groq в integration. Отдельно проверен production entrypoint на ошибке конфигурации.
- Каталог: 329 семейств, 1000 вариантов; 2 regression cases на реальном каталоге (volume/mass SKU, неоднозначное голое число).
- Web и bot используют общий baseline parser/matcher/catalog; алгоритмы web parser и VAD в этом релизе не изменены.

Покрыто тестами: один voice — одна или несколько строк; повтор updates; несколько сотрудников; открытый доступ новым пользователям без регистрации, запрет групп/аккаунтов ботов; отсутствие сметы; oversized/long voice; перезапуск и ledger неопределённой STT-попытки; сохранённый transcript; явный retry и его предел; reply-уточнение; старые inline-кнопки; ручной товар; количество и нестандартные единицы; удаление/восстановление/склейка; отмена; навигация вариантов; финализация/экспорт; CSV formula injection; budget/cooldown/429; размер скачивания и контейнер; token-redaction; at-most-once политика неизвестного исходящего send; outbox backpressure; singleton lease; authenticated webhook с повторной доставкой по настоящему локальному HTTP; startup/shutdown webhook runtime на fake адаптерах.

## Не проверено без токенов и хостинга

- Настоящая доставка Telegram voice, file download и callback UX на телефоне.
- Реальный Groq: доступ к аккаунту, OGG/Opus образцы, accuracy русских стройматериалов, latency и фактические квоты.
- Кашель/тишина: фильтр известных текстов протестирован на одном базовом случае, эффективности против всех неречевых звуков не заявлено.
- Реальная регистрация webhook/HTTPS/proxy, idle/sleep политика площадки и persistence диска.
- Запуск на выбранном Render instance и его persistent disk.
- CI запускается при обновлении PR #10; текущий результат смотреть в GitHub. Для предыдущего build 11 run 40173206505 завершился success.

## Минимальный live smoke после подключения

1. Любой новый пользователь: `/start`, `/new Тест`, голос «ротбанд 30 килограмм 12 мешков» → одна карточка, 12 мешков; затем одно voice «цемент 20 мешков и песок 5 мешков» → две карточки и один запрос STT.
2. Ещё два voice подряд → две дополнительные строки в порядке сообщений; внутри одного voice разделение зависит от содержания перечисления, а не только от пунктуации/пауз.
3. Ответ голосом «ещё три мешка» на карточку: дописывание и переразбор; вручную исправить `/qty ID 15 мешок`.
4. Выбор товара/SKU кнопками, ручной товар, удаление/восстановление, склейка.
5. `/finish`, открыть CSV/JSON на телефоне; `new` не перезаписывает предыдущую смету.
6. Второй новый пользователь входит без регистрации и видит только свои сметы; чужие ID строк/смет не позволяют прочитать/изменить/экспортировать данные.
7. Перезапустить сервис с тем же диском: `/history` и сохранённая смета доступны, повтор webhook/update не создаёт дубликат.
8. Одна короткая речь, кашель без речи, смешанный звук: зафиксировать качество и число Groq attempts, без обещания заранее обнулить кашель.

Публикацию и реальные запросы выполнить только после возвращения владельца с токенами и выбранным хостингом.

Build 9: дополнительно проверены списки из одного текста/voice, порядок и количества отдельных строк, переносы, нумерация, точки с запятой, голосовые маркеры, повтор одного товара, размеры/десятичные числа/описательные запятые без over-split, unknown товары с явной границей, `/split` + `/merge`, атомарный отказ при лимите, provenance, retry, миграция schema v1→v2. Это проверки текста/логики, не измерение точности на живой речи.

Build 10 — исторический приватный архив со встроенным токеном. Build 11 — публичный код требует TELEGRAM_BOT_TOKEN из environment; проверены opt-in, shared listener, webhook/polling, обе health-проверки и shutdown abort. Реальный API не вызывался.

Build 12: проверены новый пользователь без ID в настройках, старый ALLOWED_USER_IDS не ограничивает вход, public voice и inline callback через HTTP, изоляция чужих history/show/export/commands/reply/callback. Ошибочные Telegram identity/группы/боты не попадают в inbox. Локально 101/101 тест PASS, syntax check и demo PASS; реальная Telegram доставка не проверена.
