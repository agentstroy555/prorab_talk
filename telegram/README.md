# Agent Stroy — Telegram service

Версия **0.3.3, build 11**. Telegram worker интегрирован в существующий web service. Основной запуск — `npm start` **из корня репозитория**. Настройки: [общий Render service](../docs/RENDER.md).

Сотрудник открывает личный чат с ботом, создаёт смету и присылает одну или несколько позиций в одном сообщении. Telegram сам записывает и отправляет аудио; браузер, MediaRecorder и Silero для определения границ здесь отсутствуют. Одна запись распознаётся целиком одним STT-запросом, затем локально разбирается на одну или несколько строк. Текстовый список также можно прислать одним сообщением. Ответ голосом на карточку — явное уточнение существующей строки.

«Смета» в этой версии — список материалов с товаром, вариантом, количеством и единицей. **Цен, расчёта стоимости, выбора поставщиков и отправки заказов нет.**

## Что работает

- `/start`, меню, `/new Объект` — создание черновика; один активный черновик на сотрудника и чат.
- Голос или обычный текст → одна/несколько строк → Groq Whisper large-v3-turbo (русский) → parser/matcher → карточка.
- Каталог: 329 семейств, 1000 SKU, из проверенного web baseline.
- `/row ID`, `/edit ID текст`, `/clarify ID текст`; ответ текстом/голосом на карточку дописывает уточнение.
- `/qty ID 30 мешок`, `/item ID название`, `/variant ID`; inline-кнопки выбора, страницы вариантов.
- `/manual ID Товар | Вариант` — ручной структурированный ввод отсутствующего товара/SKU; `/qty` задаёт любую явную единицу.
- `/delete ID`, `/restore ID`, `/merge ID1 ID2`; `/split ID` с текстом позиций на новых строках — исправление разделения.
- `/list`, `/history`, `/show ID` — просмотр только собственных смет.
- `/finish` — завершение с явным числом строк, требующих проверки; CSV (UTF-8 BOM, разделитель `;`) и JSON.
- `/export` — активная смета либо последняя завершённая; `/cancel` требует отдельного подтверждения.
- SQLite на постоянном диске: черновики, очередь входящих и ответов, STT ledger, кэш, дедупликация updates, offset.
- Список разрешённых Telegram user IDs, личные чаты; группы не поддерживаются.
- Лимиты длительности/размера, квота запросов и аудиосекунд, cooldown по Groq 429, timeout, явный `/retry`.
- Long polling или webhook с secret header; общий HTTP listener и health endpoint.

Номера `ID` в командах — стабильные **ID строк из карточек**, а не текущие порядковые номера. Завершённая/отменённая смета остаётся в истории; редактирование завершённой сметы в этой версии не предусмотрено. Для новой сметы есть `/new`.

## Запустить без токенов

Нужен Node.js **24.x**. Внешних npm-зависимостей нет; `npm install` не нужен.

```bash
npm run check
npm test
npm run demo
```

`demo` — полностью локальная симуляция разговора, с mock Telegram/STT и SQLite в памяти. Она не выдаёт себя за проверку реального распознавания.

## Подключение

Использовать корневой `.env.example` и [инструкцию Render](../docs/RENDER.md). Для включения TELEGRAM_ENABLED=true, TELEGRAM_BOT_TOKEN, GROQ_API_KEY, ALLOWED_USER_IDS, абсолютный DB_PATH на постоянном диске. В публичном репозитории встроенного токена нет; он остаётся на приватном Drive. Команда `npm start` внутри telegram/ предназначена только для отдельного локального запуска, **не запускать её дополнительно к общему сервису**.

## Несколько позиций в сообщении

- Текст: отдельные строки, нумерованный список, точки с запятой или перечисление с названиями товаров и количеством.
- Голос: можно перечислить несколько товаров подряд, например «цемент 20 мешков и песок 5 мешков». Более явная граница — слова «следующая строка»/«следующая позиция».
- Точки и запятые сами по себе не всегда являются границами: размеры, фасовки и описание одного товара остаются вместе.
- Бот сообщает число получившихся строк и выдаёт карточку на каждую. Сложные/неизвестные перечисления могут потребовать `/split` или `/merge`: алгоритм эвристический, настоящая речь ещё не проверена.
- Ответ на карточку и `/clarify` по-прежнему уточняют одну выбранную строку. Для добавления нового списка отправьте обычное сообщение без reply.
- Одно сообщение — до 50 строк, 12000 символов суммарно, до 2000 на строку, в пределах 200 строк сметы. При превышении не добавляется часть списка молча.
- Полный исходный текст остаётся в inbox/voice transcript; `source_parts` связывает одно сообщение со всеми созданными строками.
